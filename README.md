## Контрольные вопросы

1. **В чём заключается принцип работы стека (LIFO)?**  
   Работает по принципу **Last In — First Out**: последний добавленный элемент извлекается первым. Основные операции: `push` — добавить на вершину, `pop` — снять с вершины, `peek/top` — посмотреть вершину.

2. **В чём заключается принцип работы очереди (FIFO)?**  
   Работает по принципу **First In — First Out**: первым извлекается тот элемент, который был добавлен раньше всех. Добавление — в хвост (`enqueue`), извлечение — из головы (`dequeue`).

3. **Чем дек отличается от очереди?**  
   **Дек** позволяет добавлять и удалять элементы **с обоих концов** за O(1). Обычная очередь — только добавление в хвост и удаление из головы.

4. **Что такое приоритетная очередь? Где она применяется?**  
   Это структура, где каждый элемент имеет приоритет; извлекается элемент с наибольшим или наименьшим приоритетом. Применяется в: T*, планировании задач, имитационном моделировании событий, обработке прерываний и т.п.

5. **Как реализовать стек на основе динамического массива?**  
   Храним массив `a`, размер `size` и ёмкость `capacity`.  
   - `push(x)`: если `size == capacity`, увеличить массив (обычно в 2 раза); `a[size++] = x`.  
   - `pop()`: если пусто — ошибка; вернуть `a[--size]`.  
   - `top()`: вернуть `a[size-1]`.  
   Сложность: `push/pop` — амортизированно O(1), в худшем случае `push` при расширении O(n).

6. **Как реализовать очередь на основе кольцевого буфера?**  
   Массив фиксированной ёмкости `N`, индексы `head`, `tail`, счётчик `size`.  
   - `enqueue(x)`: если `size == N` — расширить или ошибка; `a[tail] = x; tail = (tail + 1) % N; size++`.  
   - `dequeue()`: если `size == 0` — ошибка; `x = a[head]; head = (head + 1) % N; size--; return x`.  
   Сложность O(1).

7. **Почему приоритетную очередь обычно реализуют на куче?**  
   Двоичная куча даёт:
   - `peek` — O(1),
   - `insert` — O(log n),
   - `extractMin/Max` — O(log n).  
   Это хороший баланс. Например, сортированный массив даёт `insert` O(n), а неупорядоченный — `extract` O(n). Куча также эффективна по памяти и хорошо ложится на массив.

8. **Какова сложность операций push и pop в стеке?**  
   Для массива: амортизированно O(1), худший `push` при расширении — O(n).  
   Для связного списка: O(1) для `push` и `pop`.

9. **Какова сложность операций enqueue и dequeue в очереди?**  
   Для кольцевого буфера и связного списка — O(1).  
   Для динамического массива с расширением — амортизированно O(1).

10. **Какова сложность операций в приоритетной очереди? Почему?**  
    Для двоичной кучи:
    - `peek` — O(1),
    - `insert/push` — O(log n),
    - `extractMin/Max/pop` — O(log n),
    - построение кучи из n элементов — O(n).  
    Почему: куча хранит частичный порядок; при вставке/удалении нужно «поднимать» или «опускать» элемент по высоте дерева, а высота двоичной кучи — O(log n).

11. **Как проверить правильность расстановки скобок с помощью стека?**  
    Идём по строке:
    - открывающая скобка `(`, `[`, `{` → `push` в стек;
    - закрывающая → проверить, что стек не пуст и на вершине парная открывающая; если да — `pop`, иначе ошибка.  
    В конце стек должен быть пуст. Сложность O(n), память O(n).

12. **Как реализовать очередь на двух стеках? Какова сложность?**  
    Есть `in` и `out`.
    - `enqueue(x)`: `in.push(x)` — O(1).
    - `dequeue()`: если `out` пуст, переложить все элементы из `in` в `out` (при этом порядок перевернётся); затем `out.pop()`.  
    Сложность: `dequeue` в худшем случае O(n), но **амортизированно O(1)**, так как каждый элемент перекладывается не более одного раза. Память O(n).

13. **Как реализовать дек на основе двусвязного списка?**  
    Узлы имеют `prev`, `next`, `value`; храним указатели `head` и `tail`.  
    - `push_front/push_back` — вставка перед `head` / после `tail`;
    - `pop_front/pop_back` — удаление `head` / `tail`.  
    Все операции O(1). Минус — накладные расходы памяти на указатели.

14. **Как реализовать дек на основе кольцевого буфера?**  
    Массив ёмкости `N`, индекс `head`, размер `size`. Индекс i-го элемента: `(head + i) % N`.  
    - `push_back(x)`: `a[(head + size) % N] = x; size++`;
    - `push_front(x)`: `head = (head - 1 + N) % N; a[head] = x; size++`;
    - `pop_front()`: `head = (head + 1) % N; size--`;
    - `pop_back()`: `size--`.  
    При заполнении массив расширяется. Операции O(1) амортизированно.

15. **Как реализовать стек с поддержкой получения минимума за O(1)?**  
    Нужен вспомогательный стек минимумов.  
    - `push(x)`: `data.push(x)`; если `minStack` пуст или `x <= minStack.top()`, то `minStack.push(x)`.
    - `pop()`: если `data.top() == minStack.top()`, то `minStack.pop()`; затем `data.pop()`.
    - `getMin()`: вернуть `minStack.top()`.  
    Все операции O(1), дополнительная память O(n). Вариант без второго стека — хранить в стеке пары `(значение, текущий минимум)`.
